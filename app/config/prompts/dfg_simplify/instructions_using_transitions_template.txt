### DFG FORMAT ###
The DFG is expressed as a single JSON object with the following structure:

{
  "start_activities": [
    { "activity": "<ACT_ID_or_name>", "freq": <integer> },
    ...
  ],
  "end_activities": [
    { "activity": "<ACT_ID_or_name>", "freq": <integer> },
    ...
  ],
  "transitions": [
    { "src": "<ACT_ID_or_name>", "tgt": "<ACT_ID_or_name>", "freq": <integer> },
    ...
  ]
}

Each activity is identified by a string (for example an ACT_ID like "ACT_0", "ACT_1", ...).
The frequencies are integers representing how often the activity or transition appears.

- You MUST remove at least 50% of the transitions compared to the original model.
- You MUST retain at least 20% of the original transitions.
- For every retained activity you MUST keep at least its most relevant incoming and outgoing transitions.
- You MUST NOT invent new activities: only use activity identifiers that already appear in the input.
- You MUST NOT invent new transitions: any transition you keep MUST already exist in the input with the same src and tgt.
- Each (src, tgt) pair MUST appear at most once in the output (no duplicate transitions).
